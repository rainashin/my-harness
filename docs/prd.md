# To-Do Planner PRD — 월·주·일을 연결하는 개인 실행 관리 서비스

문서 상태: 개정 초안 · 정책 확인 필요  
작성일: 2026-09-30  
내용 기준: `to-do-planner/PRD.md` v0.9 (2026-09-08)  
대상 독자: 서비스 기획, UX/UI 디자인, 프론트엔드, 백엔드, QA

> 이 문서의 제품 요구사항은 To-Do Planner의 기존 PRD에서 가져왔다. 월간 화면은 사용자의 결정에 따라 달력 기준 4~6주차를 표시하며, 각 주는 목요일이 속한 달에 귀속한다. 체크리스트형 계산은 원본 권장안을 따르되 최종 확정이 필요하다.

---

## 1. 배경

여러 목표를 병행하는 개인은 매일 할 일을 처리하면서도 그 행동이 이번 주와 이번 달의 중요한 목표에 얼마나 기여했는지 확인하기 어렵다. 종이 월간표, 노트, 캘린더, 투두 앱을 오가면 같은 내용을 중복 입력하거나 진행 상황을 직접 계산하게 된다. 급한 일에 실행이 몰리면 다른 목표 영역이 방치된 사실을 월말에야 발견하기도 한다.

일반 투두 앱은 오늘의 할 일을 기록하고 완료하는 데, 팀 프로젝트 도구는 협업과 배정에 초점을 맞춘다. To-Do Planner는 개인이 월간 방향을 세우고 주간 계획과 일간 행동으로 분해한 뒤, 실행 결과를 다시 상위 목표에서 확인하는 흐름을 제공한다.

해결할 문제는 다음과 같다.

1. 월 목표와 오늘의 할 일이 서로 떨어져 있어 중요한 일의 실행량을 판단하기 어렵다.
2. 주차별 계획량과 실제 완료량, 남은 양을 한곳에서 비교하기 어렵다.
3. 여러 목표 영역 중 실행이 부족한 영역을 뒤늦게 발견한다.
4. 완료·취소·날짜 이동을 반복할 때 진행률을 수작업으로 맞추기 어렵다.

첫 검증 대상은 제작자 본인이다. 이후 같은 문제를 가진 1인 사업자, 프리랜서, 여러 생활 목표를 관리하는 개인에게 확장할 수 있는지 확인한다.

## 2. 제품 비전

사용자가 **위에서 아래로 계획하고, 아래에서 위로 달성도를 확인**하도록 돕는다.

> To-Do Planner는 목표 영역별 월 목표를 주차별 목표와 일간 할 일로 연결하고, 일간 완료 기록을 주간·월간 실적과 진행률에 반영하는 개인 실행 관리 서비스다.

핵심 흐름:

```text
월간 방향 설정 → 주차별 배분 → 날짜별 실행 → 주간 진척 확인 → 월간 목표 조정
```

제품 원칙:

1. 접속하면 이번 주와 오늘의 미완료 할 일을 먼저 보여준다.
2. 목표 연결은 권장하지만 생활 업무를 기록할 수 있도록 미연결 할 일도 허용한다.
3. 사용자가 계획을 직접 세운다. 서비스는 구조, 실행 현황, 계산 근거를 제공한다.
4. 완료 결과는 중복 입력 없이 상위 목표에 반영한다.
5. 월간 화면에서 목표 영역 간 상태를 비교할 수 있게 한다.
6. 개인용 도구의 가벼움을 유지한다.

## 3. 핵심 유저스토리

### 3-1. 월간 계획을 세우는 사용자로서

**여러 목표 영역을 관리하는 개인 사용자로서**, 이번 달에 달성할 결과를 영역별로 등록하고, 이를 주차별 분량으로 나누고 싶다. 월 목표값과 주차별 계획량 합계가 맞지 않아도 계획을 저장하되 차이를 알고 싶다. (원본 US-01, US-02)

### 3-2. 오늘 실행하는 사용자로서

**매일 접속하는 사용자로서**, 이번 주와 오늘이 자동으로 선택되고 오늘의 미완료 할 일이 먼저 보이길 원한다. 날짜별 할 일을 추가하고 필요하면 주차별 목표와 기여량을 연결하고 싶다. (US-03, US-04)

### 3-3. 완료 결과를 확인하는 사용자로서

**할 일을 완료한 사용자로서**, 한 번의 완료 처리만으로 주간·월간 목표의 실적이 정확히 바뀌는 것을 보고 싶다. 완료를 취소하거나 기여량·연결 목표를 수정해도 결과가 중복되거나 남지 않아야 한다. (US-05)

### 3-4. 주간 계획을 조정하는 사용자로서

**한 주를 점검하는 사용자로서**, 월요일부터 일요일까지의 계획과 완료 상태, 목표별 계획량·완료량·남은 양을 비교하고 미완료 할 일을 다른 날짜나 다음 주로 옮기고 싶다. (US-06)

### 3-5. 월간 방향을 점검하는 사용자로서

**여러 영역의 목표를 병행하는 사용자로서**, 목표 영역과 해당 월에 걸친 4~6개 달력 주차를 한 화면에서 비교해 지연되거나 방치된 목표를 발견하고, 해당 주의 화면으로 이동해 계획을 조정하고 싶다. (US-07)

### 3-6. 반복 계획을 만드는 사용자로서

**비슷한 목표를 매달 세우는 사용자로서**, 전월의 목표 구조를 새달에 복사하고 싶다. 이전 달의 실적과 완료 상태는 복사되지 않아야 한다. 복사 범위의 세부 정책은 아직 확정되지 않았다. (US-08)

## 4. 사용자들의 상황

- **제작자 본인:** 콘텐츠 제작, 영업, 외주, 학습, 운동을 한 달 안에서 함께 관리한다. 실제 업무 데이터로 핵심 사용 흐름을 먼저 검증한다.
- **멀티 프로젝트형 1인 사업자:** 여러 업무를 수행하지만 매출이나 핵심 프로젝트에 연결된 일을 충분히 했는지 판단하기 어렵다.
- **납기 중심 프리랜서:** 고객 업무가 급해 개인 브랜딩이나 학습 목표를 뒤로 미룬다.
- **균형 관리형 개인:** 일간 투두를 계속 작성해도 월간 방향과의 연결이 보이지 않는다.

초기에는 직업보다 행동 특성, 즉 **여러 목표 영역을 동시에 관리하고 일간 실행과 월간 방향을 연결하려는 사람**을 기준으로 사용성을 검증한다. 업무 배정·승인, 간트차트, 분 단위 시간 기록, 자동 계획 생성이 주목적인 사용자는 현재 대상에서 제외한다.

제품 사용 맥락:

- 데스크톱 웹에서 월간·주간 계획을 세우는 흐름을 우선한다.
- 모바일 웹에서는 오늘 할 일 확인과 완료가 가능해야 한다.
- 할 일 자체는 상위 목표와 연결하지 않아도 기록할 수 있다. 그 경우 진행률에는 반영하지 않고 미연결 상태를 표시한다.
- 월간 화면은 해당 월과 겹치는 월요일~일요일 달력 주차를 4~6개 표시한다. 월 경계에 걸친 주는 목요일이 속한 달에 귀속하며, 월~일 전체의 실적을 그 달에 반영한다.

## 5. 핵심 정보 구조

기본 데이터 계층:

```text
[목표 영역]
  └─ [월 목표: 수량형 또는 체크리스트형]
       └─ [주차별 목표: 목요일이 대상 월에 속하는 달력 주차]
            └─ [일간 할 일: 날짜에 소속, 주차별 목표 연결은 선택]
```

주요 화면과 진입 관계:

```text
[주간 현황: 기본 진입]
이번 주 → 오늘 자동 선택 → 일간 할 일 확인·완료·이동
주차별 목표와 월 목표의 진행률 확인

[월간 현황]
목표 영역 × 해당 월의 4~6개 달력 주차 → 월 목표·주차별 목표 비교
특정 주차 선택 → 해당 주간 현황으로 이동

[목표 생성·수정]
월간 현황에서 목표 영역 관리, 월·주·일 항목 생성·수정
```

필수 상태는 예정, 진행 중, 완료, 초과 달성, 보류다. 목표가 없거나 주차 계획이 비어 있거나 할 일이 미연결된 경우를 화면에서 구분한다. 월간 화면에는 대상 월과 겹치는 4~6개 주를 표시하지만, 그중 월 목표를 계획·집계하는 주는 목요일이 대상 월에 속한 4~5개 주다. 나머지는 인접 월 소속임을 구분한다. 주간 화면의 7일 배치와 모바일 월간 화면의 최종 표현은 미확정이다.

## 6. 기능 요구사항

원본의 FR-01~FR-20을 기준으로 한다. 아래의 `Must`, `Should`, `Could`, `Won't`는 원본 우선순위다. 원본에서 `포함 검토`인 항목을 확정 기능으로 취급하지 않는다.

### 6-1. 사용자 설정과 목표 영역

**필수 기능**

1. 사용자 시간대와 주 시작 요일 저장. 기본 주 시작 요일은 월요일. (FR-01 · Must)
2. 목표 영역의 생성, 이름·색상 수정, 순서 변경, 비활성화. (FR-02 · Must)
3. 여러 영역을 동시에 관리하고 월간 화면에서 영역별 목표를 비교.

입력 부담을 줄이기 위해 직전에 사용한 영역과 상위 목표를 먼저 노출한다. 기본 영역을 제공할지는 확인이 필요하다.

### 6-2. 월 목표와 주차별 목표

**필수 기능**

1. 월 목표 생성·조회·수정·삭제. 목표 영역, 제목, 대상 월, 측정 방식, 목표값·단위(수량형), 완료 방식과 선택 메모를 다룬다. (FR-03 · Must)
2. 월 목표에 연결된 주차별 목표 생성·조회·수정·삭제. 목표명, 주차, 계획값, 완료 조건, 선택 메모를 다룬다. (FR-04 · Must)
3. 주차별 계획량 합계가 월 목표값보다 적거나 많으면 미배분 수량 또는 초과 계획을 표시하되 저장은 허용한다.
4. 목표값을 넘은 실적은 100%에서 자르지 않고 초과 달성으로 표시한다.
5. 월 목표와 주차별 목표 삭제 시 영향 범위를 안내하고, 하위 일간 할 일은 미연결 상태로 보존한다.

**MVP 포함 기능 (원본 우선순위 Should)**

- 전월 목표와 구조 복사. 완료 상태와 실적은 복사하지 않고, 같은 이름의 목표가 있으면 중복 가능성을 알린다. 세부 복사 범위는 미확정이다. (FR-13 · Should, 원본 MVP 포함)

**포함 검토 기능**

- 삭제 확인과 최근 삭제 항목 복구. 최소 7일 복구는 원본 권장안이다. (FR-14 · Should, 원본 MVP 포함 검토)
- 목표·할 일의 메모. (FR-16 · Could, 원본 MVP 포함 검토)

### 6-3. 일간 할 일과 목표 연결

**필수 기능**

1. 날짜별 할 일 생성·조회·수정·삭제. (FR-05 · Must)
2. 일간 할 일을 주차별 목표에 연결하거나 연결 해제. 월 목표는 해당 주차별 목표를 통해 연결한다. (FR-06 · Must)
3. 수량형 목표에 연결되는 할 일의 완료 기여량 입력·수정.
4. 미연결 할 일은 날짜별 목록에 표시하고 상위 진행률에서는 제외한다.
5. 동일 날짜에 같은 이름의 할 일이 있으면 중복 가능성을 알린다.
6. 미완료 할 일을 다른 날짜 또는 다음 주로 이동. 자동 이월 여부는 미확정이다. (FR-12 · Should, 원본 MVP 포함)

일간 할 일은 원본 권장안에 따라 MVP에서 하나의 주차별 목표에만 연결한다. 다중 연결은 미확정 확장 사항이다.

### 6-4. 완료와 진행률

**필수 기능**

1. 일간 할 일 완료·완료 취소, 완료 시각 저장. (FR-07 · Must)
2. 완료된 하위 항목을 근거로 주차별·월 목표의 실적과 진행률 자동 반영. (FR-08 · Must)
3. 같은 완료 상태를 반복 처리해도 실적을 중복 반영하지 않는다.
4. 완료 취소 시 기존 기여량을 정확히 되돌린다.
5. 완료된 할 일의 기여량·연결 목표·날짜가 바뀌면 관련 상위 목표를 재계산한다.
6. 주간·월간 화면은 같은 원천 데이터에서 계산한 값을 보여준다.

**계산 규칙**

| 유형 | 주차별 목표 | 월 목표 |
| --- | --- | --- |
| 수량형 | 해당 목표에 연결된 완료 할 일의 기여량 합계 ÷ 주차별 계획값 × 100 | 연결된 완료 할 일의 기여량 합계 ÷ 월 목표값 × 100 |
| 체크리스트형 | 완료된 연결 할 일 수 ÷ 연결된 전체 할 일 수 × 100 | 완료된 주차별 목표 수 ÷ 전체 주차별 목표 수 × 100 |

수량형 공식의 분모가 없는 경우, 체크리스트형 목표에 하위 항목이 없는 경우는 별도 상태로 처리한다. 원본은 하위 항목이 없을 때 직접 완료를 허용하며, 체크리스트형 월 목표 공식은 v1.0 전환 전 최종 확정이 필요하다고 명시한다. 남은 목표량은 `max(목표값 − 실적, 0)`, 초과 달성량은 `max(실적 − 목표값, 0)`이다.

### 6-5. 주간 현황

**필수 기능**

1. 앱 진입 시 사용자 시간대 기준으로 이번 주와 오늘을 자동 선택. (FR-09 · Must)
2. 월요일~일요일 날짜, 날짜별 할 일과 완료 여부 표시. 오늘을 강조하고 미완료를 먼저 보여준다.
3. 주차별 목표명, 연결된 월 목표·영역, 계획량, 완료량, 진행률, 남은 양 표시.
4. 이전·다음 주 탐색, 특정 날짜 선택, 오늘로 복귀. (FR-11 · Must)
5. 할 일 생성·수정·삭제·완료·취소·연결·날짜 이동과 주차별 목표 관리.
6. 할 일이 없는 날, 주차별 목표가 없는 주, 미연결 할 일, 초과 달성, 과거 미완료 상태를 구분.

주간 화면은 오늘 할 일 확인까지의 단계를 최소화해야 한다. 7일을 한 화면의 열로 모두 보여줄지, 선택한 하루의 상세와 주간 요약을 나눌지는 미확정이다.

### 6-6. 월간 현황

**필수 기능**

1. 목표 영역·월 목표를 세로축, 해당 월과 겹치는 월요일~일요일 달력 주차 4~6개를 가로축으로 표시. 목요일이 해당 월에 속하지 않는 주는 인접 월 주차로 표시하고 해당 월 목표의 계획·실적에는 합산하지 않는다. (FR-10 · Must, 원본의 고정 1~5주차에서 변경)
2. 목표값, 완료량, 진행률, 남은 양, 주차별 계획량과 완료량, 계획이 없는 주차 표시.
3. 이전·다음 달 탐색과 이번 달 복귀. (FR-11 · Must)
4. 특정 주차를 선택하면 해당 날짜 범위의 주간 현황으로 이동.
5. 목표 없음, 주차 미배분, 계획 대비 지연, 완료, 초과 달성 상태 구분.
6. 이전 달 데이터를 보존하고 월간·주간 화면 간 계산 결과 일치.

모바일에서는 전체 표를 그대로 축소하는 방식 외에 영역별 카드 또는 가로 스크롤을 검토한다. 각 주차에는 실제 날짜 범위와 소속 월을 병기한다. 월 경계 주차를 선택하면 월~일 전체의 주간 현황으로 이동한다.

### 6-7. 보조 기능과 제외 범위

- 목표 영역·완료 상태 필터는 `Could`, MVP 제외 가능. (FR-15)
- 오늘 할 일·주간 점검 알림은 `Could`, 이번 MVP 제외. (FR-17)
- 캘린더·노션·다른 투두 서비스 연동은 이번 MVP 제외. (FR-18 · Won't)
- AI 목표 추천·자동 분해·일정 재배치는 이번 MVP 제외. (FR-19 · Won't)
- 협업·업무 배정·댓글·팀 권한은 이번 MVP 제외. (FR-20 · Won't)

## 7. 권한 구조

이 서비스의 원본 PRD는 **개인 계정과 사용자별 데이터 분리**를 MVP에 포함한다. 팀 협업과 업무 배정은 MVP 범위에서 제외한다.

### 7-1. 인증되지 않은 방문자

개인 목표와 할 일 데이터에 접근할 수 없다. 가입·로그인 화면의 구체적인 정보 구조는 원본에 정의되지 않았다.

### 7-2. 개인 사용자

- 자신의 목표 영역, 월 목표, 주차별 목표, 일간 할 일을 생성·조회·수정·삭제한다.
- 자신의 주간·월간 진행 상황을 확인한다.
- 사용자 시간대와 주 시작 요일을 저장한다.
- 다른 사용자의 개인 데이터에 접근할 수 없다.

원본 MVP 범위를 유지하므로 외부 베타용 MVP에는 계정과 사용자별 데이터 분리가 포함된다. 그 전에 제작자 개인 프로토타입을 로컬 저장으로 운영할 수 있는지와 서버 전환 시점은 별도로 결정한다. 인증 화면과 서버 동기화의 세부 동작은 원본에 정의되지 않았다.

관계·보존 규칙:

- 하나의 주차별 목표는 하나의 월 목표에 속한다.
- 주차는 월요일~일요일을 한 단위로 두고, 그 주의 목요일이 속한 달을 소속 월로 정한다. 월 목표의 `target_month`와 주차 소속 월이 일치해야 한다.
- 해당 주에 연결된 완료 할 일은 날짜가 월 경계 밖에 있어도 월~일 전체를 소속 월의 주차별·월 목표 실적에 반영한다. 같은 주의 실적을 인접한 두 달에 중복 합산하지 않는다.
- 일간 할 일의 주차별 목표 연결은 선택이며, MVP에서는 한 개까지만 연결한다.
- 월·주 목표 삭제 시 일간 할 일 자체는 보존하고 `weekly_goal_id`를 비워 미연결로 전환한다.
- 계산 결과를 캐시하더라도 원천 데이터에서 재계산할 수 있어야 한다.

## 9. MVP 범위

### MVP 1차 — 개인의 계획·실행·확인 한 사이클

**원본 PRD의 포함 범위**

1. 개인 계정과 사용자별 데이터 분리
2. 목표 영역 및 월·주·일 목표 관리
3. 월→주→일 연결과 미연결 할 일
4. 수량형·체크리스트형 진행률
5. 이번 주·오늘 자동 선택과 주간 현황
6. 목표 영역×주차 월간 현황
7. 완료·완료 취소와 상향식 실적 반영
8. 날짜 이동과 미완료 이월
9. 전월 목표 구조 복사
10. 기본 반응형 대응과 핵심 분석 이벤트

**원본에서 포함 검토 또는 제외 가능**

- 삭제 확인·최근 삭제 복구, 메모: 포함 검토
- 목표 영역·완료 상태 필터: 제외 가능

**이번 MVP 제외**

- 팀 협업·업무 배정·댓글·승인
- AI 목표 추천·자동 분해·일정 재배치
- 캘린더·노션·다른 투두 앱 연동
- 푸시·이메일 알림
- 고급 반복 일정, 간트차트, 타이머, 파일 첨부, 소셜, 결제·구독

### MVP와 개인 프로토타입의 경계

사용자 결정에 따라 원본 MVP 범위를 유지한다. 따라서 개인 계정, 전월 목표 구조 복사, 핵심 분석 이벤트는 MVP 요구사항이다. 개인 로컬 프로토타입을 먼저 운영한다면 그 종료 조건과 계정 기반 저장으로 전환할 시점을 별도로 정해야 한다. 주차 표시 방식은 달력 기준 4~6개로 변경한다.

## 10. 전체 로드맵

원본 일정은 1인 기획·디자인과 소규모 개발을 가정한 초안이다. 인력과 기술 스택이 정해지면 기간을 다시 산정한다.

### Phase 0. 정책 확정 · 원본 M0, 2~3일

- 목요일 기준 주차 소속 월의 화면 표시와 월 목표 연결 검증
- 체크리스트형 진행률과 직접 완료 조건
- 저장 방식, MVP 범위, 목표 연결 규칙

### Phase 1. UX 구조 설계 · 원본 M1, 4~5일

- 최초 설정, 오늘 실행, 주간·월간 점검 흐름
- 화면 상태, 정보 구조, 와이어프레임
- 주간 7일 표현과 모바일 월간 화면 대안

### Phase 2. 기반 구현 · 원본 M2, 5~7일

- 데이터 모델, 저장, 목표 영역·월 목표·주차별 목표 CRUD
- 사용자별 데이터 분리 정책 반영

### Phase 3. 주간 현황 · 원본 M3, 5~7일

- 이번 주·오늘 자동 선택
- 일간 할 일의 생성·연결·완료·이동
- 주차별 실적과 월 목표 반영

### Phase 4. 월간 현황 · 원본 M4, 5~7일

- 목표 영역×주차 표
- 월간 진행률과 주간 화면 이동
- 전월 목표 구조 복사 범위 결정 및 구현

### Phase 5. 안정화 · 원본 M5, 4~5일

- 반응형·접근성, 계산 자동 테스트, 분석 이벤트, 오류 수정
- 주요 브라우저와 데이터 보존 검증

### Phase 6. 개인 베타 · 원본 M6, 2주

- 제작자의 실제 월간 계획으로 2주 이상 사용
- 계산 오류와 반복적으로 불편한 입력 단계 기록

### Phase 7. 제한 베타 · 원본 M7, 2주

- 5~10명의 타겟 사용자 참여
- 핵심 과업 성공률과 2주차 재방문율 측정
- 정식 MVP 전에 해결할 우선 문제 3개 선정

게이트: Alpha는 목표 연결과 상향식 완료 반영, 개인 베타는 실제 사용과 계산 오류 0건, 제한 베타는 과업 성공률·재방문율 측정으로 판단한다.

## 11. 비즈니스 목표와 확장 가설

원본 PRD는 **유료 가치 후보를 발굴한다**는 제품 목표만 제시한다. 가격, 과금 단위, 결제 흐름, 수익 목표는 정하지 않았으며 결제·구독은 MVP에서 제외했다.

검증 순서:

1. 제작자 본인이 실제 업무에서 지속적으로 사용하는지 확인한다.
2. 1인 사업자·프리랜서에게 같은 문제가 있는지 검증한다.
3. 반복 사용을 만드는 핵심 기능과 유료 가치 후보를 찾는다.

후속 단계 후보는 주간·월간 회고, 목표 템플릿, 반복 목표, 계획 대비 실제 추세, 데이터 내보내기, 외부 연동이다. 이 목록은 기능 후보이며 유료 기능 확정안이 아니다.

## 12. 예시 목표와 실행

### 9월 스레드 30개 발행

```text
목표 영역: SNS
월 목표: 9월에 스레드 30개 발행
측정 방식: 수량형
월 목표값: 30개

1주차 목표: 스레드 7개 발행
월요일 할 일: 주제 3개 선정
월요일 할 일: 스레드 1개 작성
```

`스레드 1개 작성`을 완료하고 기여량을 1로 기록하면 연결된 주차별 목표와 월 목표의 실적이 각각 1 증가한다. `주제 3개 선정`처럼 발행 수량에 직접 기여하지 않는 행동은 기여량 입력·연결 방식을 명확히 해야 한다. 위 예시는 계산 방향을 보여주며 특정 할 일의 기여량을 임의로 확정하지 않는다.

체크리스트형 목표의 예시는 `홈페이지 리뉴얼`이다. 원본은 하위 완료 수로 진행률을 계산하는 권장안을 제시하지만, 크기가 다른 단계에 동일 가중치를 줄지 결정이 필요하다.

## 13. 성공 지표

아래 수치는 원본 PRD에서 **출시 전 기준값이 없는 검증 가설**로 제시했다. 내부 사용 2주 후 기준선을 측정하고 조정한다.

### 계획·연결 지표

| 지표 | 측정 방식 | 가설 목표 |
| --- | --- | --- |
| 목표 계층 설정 완료율 | 신규 사용자 중 24시간 내 월·주·일 항목을 1개 이상 연결한 비율 | 60% 이상 |
| 일간 할 일 연결률 | 생성된 일간 할 일 중 월·주 목표에 연결된 비율 | 70% 이상 |
| 핵심 과업 성공률 | 도움 없이 월→주→일 연결을 완료한 테스트 참가자 비율 | 80% 이상 |

### 실행·유지 지표

| 지표 | 측정 방식 | 가설 목표 |
| --- | --- | --- |
| 주간 계획 실행률 | 완료된 예정 할 일 ÷ 해당 주 예정 할 일 | 기준선 대비 2주차 개선 |
| 2주차 주간 재방문율 | 가입 2주차에 주간 현황을 1회 이상 사용한 비율 | 40% 이상 |
| 월간 현황 확인률 | 주간 활성 사용자 중 월간 탭을 주 1회 이상 확인한 비율 | 50% 이상 |

### 사용성·품질 지표

| 지표 | 측정 방식 | 가설 목표 |
| --- | --- | --- |
| 오늘 할 일 확인 시간 | 접속 후 오늘의 미완료 항목 인지까지의 중앙값 | 10초 이내 |
| 진행률 계산 오류율 | 검증 시나리오에서 실제 값과 표시 값의 불일치 비율 | 0% |

함께 볼 가드레일은 목표 생성 중 이탈, 연결 대상 탐색 오류, 삭제 후 복구 실패, 작은 화면의 가로 스크롤 문제, 미완료 할 일 과다 누적이다. 분석 이벤트에는 목표명·할 일명·메모의 원문을 기본 수집하지 않는다.

## 14. 조건과 미확정 결정

**제품·품질 조건**

- 데스크톱 웹을 우선하되 모바일에서 오늘 할 일 확인과 완료는 가능해야 한다.
- 주간 핵심 콘텐츠 2초 이내, 완료 후 체감 갱신 300ms 이내, 월간 전환 1초 이내를 목표로 한다.
- 키보드만으로 날짜 선택·할 일 생성·완료가 가능해야 한다. 상태는 색상 외 텍스트·아이콘으로도 구분하며 WCAG 2.2 AA 수준의 명암비를 목표로 한다.
- 최신 Chrome, Edge, Safari 및 최신 iOS Safari·Android Chrome을 우선 지원한다.
- 인증된 사용자만 자신의 데이터에 접근한다. 계정 기반 저장으로 전환할 경우 전송 암호화와 저장 접근 제어를 적용한다.
- 사용자 기기 시간만을 맹신하지 않고 확정된 사용자 시간대를 기준으로 오늘과 주차를 계산한다.

**개발·기획 전에 확인할 결정**

1. **결정됨:** 월간 화면에는 해당 월과 겹치는 월요일~일요일 달력 주차를 4~6개 표시한다. 각 주는 목요일이 속한 달에 귀속하며, 월~일 전체 실적을 그 달에 반영한다. 목요일이 인접 월에 있는 표시 주차는 해당 월 목표에 합산하지 않는다. 원본의 고정 1~5주차 권장안은 적용하지 않는다.
2. 첫 버전 저장 방식과 외부 베타 전 계정 기반 저장 전환 시점.
3. 체크리스트형 월 목표의 동일 가중치 계산과 하위 항목이 없을 때 직접 완료하는 조건.
4. 주간 7일 화면과 모바일 월간 화면의 최종 정보 구조.
5. 전월 복사 범위: 월 목표 구조만 또는 주차별 목표·일간 할 일까지 포함.
6. 미완료 항목의 자동 이월 여부, 기본 목표 영역 제공 여부, 예상 시간·우선순위·마감시간 필요 여부.
7. MVP 기술 스택, 개발 인력, 개인 베타 시작일과 테스트 사용자 범위.

원본의 권장안은 결정을 돕는 제안이며 이 문서 작성만으로 확정되지 않는다.

## 15. 이렇게 평가해요

### 문제 해결의 완성도

사용자가 월간 방향을 세우고 주차별 분량과 오늘 할 일을 연결한 뒤, 실행이 부족한 영역을 발견할 수 있어야 한다. 단순한 할 일 목록만으로는 핵심 문제를 해결하지 못한다.

### 계획·실행 흐름의 완성도

처음 목표를 만들고 오늘 실행하며 주간·월간 현황으로 돌아오는 흐름이 이어져야 한다. 목표 생성 과정이 길어 이탈하지 않는지도 본다.

### 진행률의 정확성과 설명 가능성

완료·취소·이동·연결 변경·삭제 후에도 상위 값이 정확해야 한다. 사용자가 어떤 완료 항목으로 숫자가 계산됐는지 설명할 수 있어야 한다.

### 화면·접근성 완성도

오늘의 미완료 할 일이 바로 보여야 하며, 데스크톱과 모바일에서 핵심 정보를 읽을 수 있어야 한다. 키보드 조작과 색상 외 상태 구분을 확인한다.

### 데이터 신뢰성과 보존

주간·월간 화면의 값이 일치하고, 재접속 후 데이터가 유지되어야 한다. 월·주 목표를 삭제해도 일간 할 일이 뜻하지 않게 사라져서는 안 된다.

### 검증 가능성

기능·계산·사용성·품질 기준을 각각 확인한다. 원본의 사용성 승인 기준은 5명 중 4명 이상이 도움 없이 목표를 연결하고 10초 이내 오늘 할 일을 찾는 것이다. 계산 자동 테스트는 모두 통과해야 하며 핵심 시나리오의 치명적·주요 결함은 0건이어야 한다.

## 16. 제출물 기준

기획·디자인·개발 산출물은 원본 PRD의 요구사항과 승인 조건을 확인할 수 있도록 다음을 포함한다.

1. 목표 영역 → 월 목표 → 주차별 목표 → 일간 할 일 정보 구조와 최초 설정 흐름
2. 핵심 사용자 흐름: 오늘 실행, 주간 점검, 월간 점검, 전월 목표 복사
3. 핵심 화면: 주간 현황, 월간 현황(목표 영역 관리 포함), 월·주·일 생성·수정 UI
4. 화면 상태: 빈 상태, 미연결, 미배분 계획, 지연, 완료, 초과 달성, 삭제 영향
5. 데이터 모델과 진행률 계산·재계산 규칙
6. 날짜·주차 매핑과 저장 방식의 확정 기록
7. 기능 수용 조건, 계산 테스트, 접근성·반응형·브라우저 확인 결과
8. 핵심 KPI와 분석 이벤트 설계. 자유 입력한 목표명·할 일명·메모 원문은 수집 대상에서 제외

이 목록은 본 PRD를 구현하고 승인하기 위한 산출물 기준이다. 확정되지 않은 정책은 결정 기록이 생길 때까지 미정으로 표시한다.
