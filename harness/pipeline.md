작성일: 2026-09-30
근거: story-work.md(단계·게이트), purpose.md(완료 기준)

## 흐름

```text
[1. 레퍼런스 분석] → 게이트 1 → [2. 화면 설계] → 게이트 2 → [3. 디자인 제작] → 가이드 검토(완료 조건) → 본인 컨펌
```

## 단계별 입력과 출력

| 단계 | 포함 작업 (story-work.md) | 입력 | 출력 |
|---|---|---|---|
| 1. 레퍼런스 분석 | 1, 2 | prd.md, 대상 화면 목록 | 레퍼런스 목록 10개(UIBowl 링크, 화면 유형, 선택 이유), 표현 방식 비교표(방식 4개, 방식마다 장점·단점), Figma 01_Reference |
| 2. 화면 설계 | 3 | 비교표, prd.md, story-service.md | 화면 설계 문서 A안·B안(화면별 표시 정보, 우선순위, 배치 방식), Figma 02_Screen Spec |
| 3. 디자인 제작 | 4, 5, 6, 7 | 설계 문서 A안·B안, design.md | Figma 03_Design 시안 A안·B안, 가이드 판정용 노드 JSON |

표현 방식 4개는 story-work.md 2번 작업의 네 가지다. 주간 7일 배치, 오늘 할 일 강조, 태스크 단위 보기, 월간 보기다.

## A안과 B안

- A안: 7일을 한 화면에 열 7개로 배치한다.
- B안: 선택한 하루의 상세와 주간 요약으로 나눈다.
- 화면 설계 문서에 "배치 방식" 항목을 두고, A안과 B안의 값이 달라야 한다.
- 근거: PRD 5장, 6-5장, 14장 4번(주간 7일 화면은 미확정).

## 디자인 제작 단계의 내부 순서

1. 키스크린을 A안·B안에 각각 그린다.
2. 공통 토큰과 컴포넌트를 design.md 값으로 만든다.
3. 대상 화면 전체로 확장한다.
4. 노드 JSON을 추출해 가이드를 검토한다. 위반 0개일 때 단계가 끝난다.
